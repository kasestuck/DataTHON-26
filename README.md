# Forte Vision — frontend + локальный AI backend

Краткая инструкция финального запуска, API, передачи ключа и известных ограничений:
[deploy/SUBMISSION.md](deploy/SUBMISSION.md). Исследовательский вариант AI не включён
в production. Перед сдачей нужно зафиксировать проверенные файлы и отдельно открыть
и проверить HTTPS-доступ; сам запуск `start.ps1` остаётся локальным.

## Быстрый запуск: локально или через HTTPS-туннель

Сайт можно запускать самостоятельно на своём компьютере или открывать к нему временный доступ через интернет с помощью Cloudflare Tunnel. В обоих режимах AI работает локально на вашей GPU.

Команды выполняются в PowerShell из папки проекта. Сначала подготовьте `.venv`, зависимости и локальные веса моделей по инструкции ниже. Для туннеля также нужен проверенный `.tools/cloudflared.exe`; подготовка описана в [deploy/PUBLISHING.md](deploy/PUBLISHING.md).

**Локально — только на своём компьютере:**

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Откройте [http://127.0.0.1:8001](http://127.0.0.1:8001).

**Через HTTPS-туннель — с публичной ссылкой для жюри:**

```powershell
# Проверка готовности без открытия доступа в интернет:
powershell -ExecutionPolicy Bypass -File .\deploy\start-public.ps1

# Запуск сайта и открытие публичного HTTPS-доступа:
powershell -ExecutionPolicy Bypass -File .\deploy\start-public.ps1 -Publish
```

Откройте HTTPS-ссылку, которую выведет команда, и передайте её жюри. Ссылка меняется при перезапуске. Компьютер должен оставаться включённым, подключённым к питанию и интернету; окно запуска должно оставаться открытым. Обладатели ссылки смогут пользоваться сайтом, трафик проходит через Cloudflare. Для первоначальной публичной проверки используйте синтетический MOV; приватные банковские видео передавайте через туннель только при наличии разрешения.

Остановка — **Ctrl+C** в окне запуска. Перед переключением между локальным и публичным режимами остановите предыдущий экземпляр, чтобы на GPU работала одна очередь анализа.

Инструкция Back 1 и контракт анализатора: [backend/analyzer/README.md](backend/analyzer/README.md).

FastAPI принимает `.mov`, ставит задания в последовательную очередь и вызывает локальный `backend.analyzer.analyze_video`. Реальный анализатор включён по умолчанию. Заглушка возвращает `[]` и доступна только при явном выборе для разработки API; она **не обнаруживает нарушения**.

## Запуск всего сайта на Windows

Запускайте команды из корня репозитория на Python 3.13.12. Веса размещаются отдельно в `models/rtdetr_r18vd` и `models/qwen3_vl_2b`; команды ниже не скачивают их.

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt -r backend/requirements-analyzer.txt
& .\.venv\Scripts\python.exe -m pip install torch==2.10.0+cu128 torchvision==0.25.0+cu128 --index-url https://download.pytorch.org/whl/cu128
& .\.venv\Scripts\python.exe -m pip install -r backend/requirements-models.txt
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Откройте **http://127.0.0.1:8001** → «ИИ-анализ» → выберите MOV → «Проверить видео». Скрипт `start.ps1` проверяет наличие локальных весов, создаёт ключ только в окружении и запускает сайт и API одним процессом. Остановка — Ctrl+C. Если `.venv` и зависимости уже готовы, достаточно одной команды `powershell -ExecutionPolicy Bypass -File .\start.ps1`. Сборка frontend и Docker для этого не нужны. Внешний доступ не включается. Порт запуска сайта — 8001 (8000 на проверенной машине уже занят другим процессом). При необходимости задайте `-Port 8080` после `start.ps1` и откройте соответствующий адрес. Занятые процессы скрипт не завершает.

`API_KEY` хранится только в окружении или приватном `.env`, не в Git и не в клиентском JavaScript. Uvicorn запускается одним процессом, очередь одним потоком. Back 2 ограничивает вызов 270 секундами, Back 1 — 260 секундами. При таймауте завершается и вложенный процесс анализатора, чтобы он не занимал GPU параллельно со следующим заданием.

В отдельном CUDA-процессе анализатора на Windows CPU-пул PyTorch ограничен одним потоком до загрузки моделей. Настройка не меняет пул FastAPI, веса, выбор кадров или JSON-грамматику. Одно VLM-окно ограничено 60 секундами и остатком общего бюджета с резервом 5 секунд на завершение. Лимиты Back 1 / Back 2 остаются 260/270 секунд; загрузка моделей входит в общий бюджет. Повторный сбой при одном CPU-потоке показал, что прежний лимит окна 35 секунд мог прервать незавершённый JSON задолго до общего дедлайна. Контролируемый стресс-тест использует искусственную задержку настоящего inference и не доказывает причину исходного замедления.

Приватные диагностические файлы находятся в `backend/analyzer/output/diagnostics/` (или `ANALYZER_TEMP_DIR/diagnostics/`): начало/конец окна, размеры кадров, токены, завершённость JSON, причины остановки, остаток бюджета, CPU/interop threads и VRAM. Тексты ответов, описания и изображения в эту телеметрию не записываются. При ошибке возвращается `failed`, без отрицательного или частичного вердикта. Для демонстрации используйте один экземпляр сервера и не запускайте прямой анализ параллельно с его очередью.

## Локальный запуск без модели

Для запуска только API с заглушкой достаточно Python 3.10+. Совместный запуск с анализатором Back 1 ориентирован на проверенный ею Python 3.13.12. Скопируйте `.env.example` в локальный `.env` и задайте длинный случайный `API_KEY`. `.env` исключён из Git. При ручном запуске через PowerShell установите переменные окружения:

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:API_KEY = "локальный-длинный-секретный-ключ"
$env:ANALYZER_TARGET = "backend.api.stub:analyze_video"
& .\.venv\Scripts\python.exe -m uvicorn backend.api.app:app_from_env --factory --host 127.0.0.1 --port 8000 --workers 1
```

Этот раздел — только для изолированной разработки API с явно выбранной заглушкой. Без `ANALYZER_TARGET` используется реальный `backend.analyzer:analyze_video`; отсутствие весов приводит к `failed`, а не к подмене анализа заглушкой. Оставьте один процесс Uvicorn (`--workers 1`).

## API и примеры

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/v1/analyze -H "X-API-Key: локальный-длинный-секретный-ключ" -F "file=@video.mov"
curl.exe http://127.0.0.1:8000/api/v1/jobs/ПОЛУЧЕННЫЙ_JOB_ID -H "X-API-Key: локальный-длинный-секретный-ключ"
curl.exe http://127.0.0.1:8000/health
```

`POST /api/v1/analyze` принимает поле `file` и возвращает `job_id`. `GET /api/v1/jobs/{job_id}` возвращает `processing`, `done` или `failed`. При `done` ответ содержит `verdict` (`violation` или `no_violation`) и массив `violations`. Каждый элемент содержит только согласованные поля `type`, `timecode_sec`, `description`, `evidence_frames` (`timestamp_sec`, `image_base64`). При `failed` возвращается безопасное для клиента поле `error`; подробная причина остаётся в серверном журнале. Оба маршрута требуют `X-API-Key`; `/health` общедоступен.

Размер файла ограничен 100 МиБ, загрузка идёт по частям. Проверяются расширение `.mov` и заголовок контейнера; полную декодируемость видео должен проверить анализатор. Очевидно повреждённый файл отклоняется с 400, превышение лимита — с 413. Задания и статусы хранятся в SQLite (`var/jobs.sqlite3`). После завершения, ошибки или таймаута исходное видео удаляется. Незавершённые задания восстанавливаются после перезапуска. Задания обрабатываются по одному; таймаут анализатора — 270 секунд. Старые осиротевшие загрузки и завершённые записи удаляются после 24 часов, проверка выполняется при старте и раз в час.

## Контракт Back 1 и правила

Back 1 предоставляет `from backend.analyzer import analyze_video`, где `analyze_video(video_path: str) -> list[Finding]`. Каждый Finding: `violation_type: str`, `timecode_sec: float`, `description: str`, `confidence: float` в диапазоне 0–1, `evidence_frames: list[EvidenceFrame]` из 1–3 кадров. Кадр: `timestamp_sec: float`, `jpeg_bytes: bytes`. Сервис валидирует Finding, кодирует JPEG в base64 и формирует `verdict`. `confidence` в публичный JSON не входит. Некорректный результат или ошибка анализатора переводит задание в `failed`.

`backend/data/violation_types.json` имеет форму `{"type_id": {"name": "Название", "description": "Визуальные признаки"}}`: 18 визуальных категорий. Отдельная `violation_type_policy.json` разрешает автоматическую выдачу 12 категорий. В `rules.json` для всех ID стоит `needs_review`; нормативные основания не выдумываются. После ручных изменений каталога выполните:

```powershell
& .\.venv\Scripts\python.exe -m backend.api.rules sync
& .\.venv\Scripts\python.exe -m backend.api.rules check
& .\.venv\Scripts\python.exe -m backend.api.risk_catalog
```

`sync` создаёт для новых ID только `{"status": "needs_review"}`. Для ручного подтверждения запись меняют на `{"status": "verified", "document": "...", "section": "...", "url": "https://..."}`. Валидатор допускает лишь HTTPS-ссылки на `adilet.zan.kz` и его поддомены либо `nationalbank.kz` и его поддомены. Проверка домена **не подтверждает содержание документа или применимость нормы**: название, раздел и правовое утверждение нужно проверить вручную по официальному тексту. Подтверждённое основание включается в `description` только при наличии проверенного пункта; форма API и Finding сохраняется.

Отдельный [risk_references.json](backend/data/risk_references.json) содержит фиксированные описания возможного риска для всех 18 визуальных категорий: 7 `contextual_reference` и 11 `internal_policy_required`, 0 `verified`. Постановление Правления Национального Банка РК от 29.11.2019 № 231 указано только как тематическая справка для кассовых операций и инкассации, без номера нарушенного пункта. Для доступа, сейфа и ключей требуется проверка применимых требований охраны и внутреннего порядка. Для внутренних вопросов явно указано «Внутренний регламент банка не предоставлен». Отдельная справочная запись не может получить `verified` без соответствующей записи и пункта в юридически проверенном `rules.json`. Подробности: [backend/data/RISK_REFERENCES.md](backend/data/RISK_REFERENCES.md).

API добавляет описание возможного риска, справочную ссылку с оговоркой и фразу «Нормативное основание требует дополнительной проверки» в существующее поле `description`, которое уже отображает интерфейс. Эти сведения не подаются VLM и не меняют обнаружение событий. Отсутствие справочного файла или подтверждённого правила допускается: результат сохраняется, показывается необходимость проверки основания.

## Редактура пользовательских текстов

Пользовательские названия 18 категорий редактируются только в поле `name`. Поле `description` в `violation_types.json` содержит инструкции для VLM и сохраняется без изменений. Описания возможных рисков находятся в отдельном `risk_references.json` и используются только после анализа.

`backend/api/display_text.py` нормализует пробелы, Unicode и пунктуацию, исправляет две однозначные орфографические ошибки и небольшой список согласованных словосочетаний, например «передача наличности» → «передача наличных денежных средств». Отрицание, степень уверенности, роли людей и содержание действий не перефразируются. Неоднозначные фразы сохраняются по смыслу; «открытая дверца» не превращается в «сейф оставлен открытым», а «проверка документа» — в подтверждённое отсутствие проверки.

Finding, ID, confidence, время событий и JPEG не изменяются. Исходный текст хранится отдельно от версии для отображения в `DATA_DIR/diagnostics/text/<job_id>.json` (по умолчанию — `var/diagnostics/text/`). Этот каталог не раздаётся сайтом и исключён из Git через `var/`. Диагностика не включается в публичный JSON; внутренние ошибки и сведения CUDA остаются в серверных журналах. Отсутствие возможности записать текстовую диагностику не меняет результат анализа и отмечается в закрытом журнале.

## Фронтенд

Готовый интерфейс FrontDEV2 находится в `frontend/`: исходный дизайн, навигация, плеер, профиль и адаптивные стили сохранены. `start.ps1` задаёт `FRONTEND_DIST` только на этот каталог. Никогда не указывайте корень репозитория: он содержит приватные файлы и Git. FastAPI раздаёт HTML/CSS/JS с `/`, приложение не требует отдельного Node-сервера.

`frontend/api.js` получает CSRF-токен через `GET /ui-api/v1/session`, отправляет файл полем `file` через `POST /ui-api/v1/analyze` и опрашивает `GET /ui-api/v1/jobs/{job_id}` каждые 2,5 секунды. Ключ сервера в браузер не попадает. Cookie — HttpOnly, SameSite=Strict; при HTTPS также Secure. Запросы с чужого origin блокируются. Сессия переиспользуется между вкладками; после 403 клиент может один раз обновить CSRF-токен. `/api/v1/*` по-прежнему требует ключ и не заменяется браузерным API. Сам интерфейс намеренно доступен без входа; перед публикацией нужен согласованный контроль доступа. Публичный доступ включается только отдельным подтверждённым запуском; состояние подготовки описано в deploy/PUBLISHING.md.

Сервер возвращает только `processing`, `done`, `failed`; ожидание в очереди тоже отображается как `processing`. Процентов прогресса нет. Браузер не ограничивает всю задачу 30 секундами или пятью минутами: очередь может увеличить ожидание. Ограничения отдельных HTTP-запросов — 60 секунд для загрузки и 15 для статуса; при ошибке polling допускаются три попытки. Неопределённо завершившаяся загрузка автоматически не повторяется, чтобы не создать дубликат задачи. Двойной клик блокируется. «Остановить ожидание» и уход со страницы прекращают запросы клиента, **не отменяют серверную обработку**.

Деморежим, ответы по имени файла и создание кадров в браузере удалены. Находки сортируются по времени, JPEG берутся только из ответа анализатора. Повреждённый кадр заменяется сообщением, а не выдуманным доказательством. Отсутствующий или некорректный verdict не превращается в `no_violation`. Для отрицательного результата поясняется, что отсутствие находок не гарантирует отсутствия нарушений. Внутренняя confidence не отображается. Тематическая ссылка явно помечается как справка, требующая проверки; проверенное нормативное основание показывается отдельно от такой справки в описании результата.

Браузерный интерфейс рассчитан на тот же origin, что и API: cookie с `SameSite=Strict` не предназначена для вызовов с другого сайта. Для разрешённых внешних клиентов API можно задать в `CORS_ORIGINS` явный список origin через запятую; `*` отклоняется. CORS сам по себе не передаёт клиенту API-ключ и не делает кросс-доменный браузерный интерфейс рабочим. Не размещайте `API_KEY` в публичных файлах.

Поле API `verdict=violation` означает найденный анализатором визуальный шаблон, **не доказанное юридическое нарушение**. Интерфейс показывает пользователю «Обнаружены признаки возможного нарушения; требуется проверка человеком и нормативного основания». Для `no_violation` корректно «Поддерживаемые системой признаки не обнаружены», а не «Нарушений нет». При `failed` нельзя показывать отрицательный вердикт. Эти ограничения отражены в текстах интерфейса.

## Docker и публичный адрес

`Dockerfile` использует Python 3.13.12, API-зависимости DEV2, манифесты Back 1 и PyTorch 2.10.0/TorchVision 0.25.0 с CUDA 12.8. Полная ML-часть обязательна для интегрированного образа. Compose выбирает реальный анализатор, выделяет GPU, монтирует веса и четыре публичных JSON-каталога только для чтения. Приватные CSV/Excel, отчёты, JPEG и веса исключены из build-контекста; весь каталог приватной разметки внутрь контейнера не монтируется. Порт публикуется лишь на `127.0.0.1`. Для сборки нужны Docker Desktop с WSL 2 и поддерживаемый драйвер NVIDIA; см. [официальный Docker GPU guide](https://docs.docker.com/desktop/features/gpu/) и [Compose GPU guide](https://docs.docker.com/compose/how-tos/gpu-support/). Во время inference включены offline-флаги и сетевой запрет Back 1.

Скопируйте `.env.example` в `.env` и задайте случайный секрет. Локальные веса должны лежать в `models/rtdetr_r18vd/` и `models/qwen3_vl_2b/` рядом с `compose.yaml`; они не копируются в образ. Сначала выполните `docker compose build` и `docker compose run --rm api python -m backend.scripts.check_environment`, затем smoke моделей/API и только после этого `docker compose up`. Docker CLI на текущей Windows-машине отсутствует: сборка и GPU внутри контейнера не проверены. Нативная проверка Windows выполняется отдельно и не заменяет Docker-сборку.

Подготовка HTTPS и отдельная команда публикации описаны в [deploy/PUBLISHING.md](deploy/PUBLISHING.md). Безопасная проверка готовности: `powershell -ExecutionPolicy Bypass -File .\deploy\start-public.ps1`. Без `-Publish` скрипт не запускает туннель. Инструмент cloudflared проверен по SHA256 и исключён из Git. Публичный URL и внешний MOV/AI-тест ещё не выполнены: сначала требуется отдельное подтверждение публикации.

## Тесты

```powershell
& .\.venv\Scripts\python.exe -m pytest -q
ruff check backend tests # При необходимости установите dev-tool: pip install ruff==0.15.22
& .\.venv\Scripts\python.exe -m pip check
& .\.venv\Scripts\python.exe -m backend.scripts.check_environment
& .\.venv\Scripts\python.exe -m backend.scripts.smoke_models --catalog-check
# Настоящий HTTP/Uvicorn + реальный MOV + локальные модели; вывод без кадров и ключей:
& .\.venv\Scripts\python.exe -m backend.scripts.smoke_api --video PATH_TO_LOCAL_VIDEO.mov --require-finding
```

Pytest собирает `backend/tests` и `tests`; тесты покрывают обе части, dataclass-контракт, декодируемый JPEG→base64, очередь, вложенный spawn, очистку дерева процессов по таймауту, закрытие SQLite-соединений, ошибки и браузерную интеграцию. Здесь используются явные синтетические компоненты. Отдельные CUDA/model/API smoke вызывают настоящие веса; `smoke_api` поднимает Uvicorn на случайном loopback-порту, отправляет реальное видео, проверяет JPEG из ответа, последовательность очереди, `failed` для повреждённого MOV и удаление временных загрузок. Секрет генерируется в памяти, исходник не изменяется, отчёт сохраняется только в игнорируемом `backend/data/reports/integration_BACK/`. Эти проверки не устанавливают качество детекции и юридическую обоснованность.

Для браузерного QA нужны Node.js, Playwright и установленный Chrome; инструкции: [tests/frontend/README.md](tests/frontend/README.md). Для работы самого сайта Node.js не нужен. Браузерный набор отдельно помечает тесты с синтетическими API-ответами и реальный AI. Скриншоты не создаются. Приватные результаты QA сохраняются только в игнорируемом `backend/data/reports/integration_fullstack/`. DOM-проверка ширин 360/390/768/1440 не заменяет вашу визуальную проверку дизайна.

Рабочая ветка проекта — **main**. Она содержит интеграцию BACK `10ce984` (DEV1 `724fb77`, DEV2 `6a27bf6`), FrontDEV2 `c9bab75` и исправление VLM timeout `d4551b6`. Другие ветки сохранены; force push не применяется.

Подтверждённые проверки исправления VLM: 181 pytest, Ruff 0.15.22, pip check и CUDA; 15 браузерных сценариев с явными синтетическими API-ответами. Реальный X-1 через браузер: 2 находки и 5 JPEG за 50,47 с. Отдельные реальные API-сценарии с другим положительным и отрицательным видео завершились за 38,33 и 53,60 с соответственно (включая запуск сервера и дополнительную проверку повреждённого MOV). Проверены реальный запуск `start.ps1` на 8001, изоляция приватных путей и отсутствие API-ключа в запросах браузера. Docker-сборка и визуальная оценка дизайна остаются непроверенными.

## Ограничения AI для демонстрации

Это экспериментальный визуальный помощник. Возможны ложные срабатывания при обычном пересчёте и передаче наличных, работе с сейфом, а также пропуски коротких действий и ошибки на другом ракурсе. Отсутствие находок не гарантирует отсутствия нарушения. Модели не устанавливают личность, намерения или юридическую виновность, не анализируют звук и не обучаются на проверочных видео. Подтверждённых нормативных оснований сейчас нет. Результат требует просмотра человеком и проверки применимого правила. Приведённые smoke-тесты проверяют интеграцию и скорость; они не доказывают точность и устойчивость модели.

Подготовка HTTPS ранее проверена локально: Secure/HttpOnly-cookie, CSRF, отказ без ключа, закрытые приватные пути и безопасный режим launcher без старта процессов. При финальной стабилизации прошли 259 production-тестов, Ruff и pip check, настоящий запуск `start.ps1`, проверка ключа и закрытых путей, а также реальный API → AI smoke-тест с двумя находками и пятью JPEG. Экспериментальные тесты в комплект сдачи не входят. Публичный туннель сейчас выключен и в ходе финальной проверки не открывался; внешний HTTPS URL нужно заново открыть и проверить после отдельного разрешения.
