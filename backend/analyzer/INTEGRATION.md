# Передача Back 1 → Back 2

## Вызов

Из корня репозитория:

```python
from backend.analyzer import analyze_video, AnalyzerError

def main():
    try:
        findings = analyze_video("path/to/input.mov")
        for finding in findings:
            assert 1 <= len(finding.evidence_frames) <= 3
            assert isinstance(finding.evidence_frames[0].jpeg_bytes, bytes)
    except AnalyzerError as error:
        # Сохранить статус ошибки задания; не подменять отрицательным вердиктом.
        raise

if __name__ == "__main__":
    main()
```

Сигнатура: `analyze_video(video_path: str) -> list[Finding]`, синхронный вызов.
Импорт не загружает веса. Успешный вызов без поддержанных находок возвращает `[]`.
Объекты — dataclass, совместимые со spawn/pickle; JPEG передаются в `bytes`.
Нормативные источники, публичный JSON, base64 и HTTP здесь не формируются.

`Finding`: `violation_type`, `timecode_sec`, `description`, `confidence`,
`evidence_frames`. `EvidenceFrame`: `timestamp_sec`, `jpeg_bytes`.

## Окружение и веса

Проверенная конфигурация: Windows 11, Python 3.13.12, RTX 4060 Laptop 8 GB,
PyTorch 2.10.0+cu128 / TorchVision 0.25.0+cu128, Transformers 4.57.6.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-analyzer.txt
.\.venv\Scripts\python.exe -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-models.txt
.\.venv\Scripts\python.exe -m backend.scripts.check_environment
```

CUDA Toolkit отдельно не требуется: используется runtime wheel. Проверка окружения
выполняет настоящее CUDA-ядро, а не только читает строку драйвера.

Веса размещаются локально:

- `models/rtdetr_r18vd/`: PekingU/rtdetr_r18vd, Apache-2.0, около 81 MB.
- `models/qwen3_vl_2b/`: Qwen/Qwen3-VL-2B-Instruct, Apache-2.0, около 4.27 GB.

У каждого каталога нужны `config.json`, safetensors, файлы процессора и tokenizer;
зафиксированные revisions и хеши находятся в `models/*/provenance.json`.
Веса исключены из Git. На целевой машине их нужно разместить отдельно.
`backend.scripts.download_models` — отдельная явная операция подготовки,
размер загрузки требует согласования; inference её не вызывает.

Для альтернативного расположения задайте `ANALYZER_DETECTOR_DIR`,
`ANALYZER_VLM_DIR`. Дополнительно доступны `ANALYZER_CATALOG`,
`ANALYZER_POLICY`, `ANALYZER_TEMP_DIR`, `ANALYZER_CONFIDENCE`.

## Каталог и пределы выводов

Обязательно передавать вместе:

- `backend/data/violation_types.json`: строго `{type_id: {name, description}}`.
- `backend/data/violation_type_policy.json`: разрешение выдачи и требования к доказательствам.

Для строгой проверки наличия политики можно задать `ANALYZER_POLICY` явно.
Все ID политики должны точно совпадать с каталогом. Из 18 предварительных
визуальных категорий разрешены 12; 6 исключены из автоматической выдачи.
Модель получает только разрешённые категории, без разметки видео и таймкодов истины.
Одинаковый тип объединяется между видео; `unknown`/`needs_review` — статусы, не ID.

Находка означает поддержку визуального шаблона кадрами, а не юридическую виновность.
Нормативные основания не установлены. Перечень для проверки — `LEGAL_REVIEW.md`.
Нельзя выводить полномочия, содержание экрана, факт проверки удостоверения,
номиналы банкнот или физическое смешивание денег из недостаточного контекста.
Сложные действия требуют 2–3 разнесённых JPEG, а переход операций — 3 кадров
с интервалом не менее 6 секунд. Кандидат содержит до 6 кадров за 10 секунд.

## Процессы, время и ошибки

Внешний лимит Back 2 — 270 с. Внутренний жёсткий дедлайн — 260 с с загрузкой
весов; завершение/очистка процесса оставляет запас до внешнего лимита.
VLM получает до 35 с на окно, включая один ограниченный повтор при неверной
JSON-схеме. Ошибка после повтора остаётся исключением.
Генерация ограничена локальной `lm-format-enforcer==0.11.3` (MIT): допустимы
только JSON-поля, ID каталога, времена переданных кадров и индексы этих кадров.
Генерация останавливается на полном JSON-объекте. Явный отрицательный ответ с
`null`-типом и `null`-временем может иметь лишние ссылки на кадры: они отбрасываются,
сам отрицательный вердикт не меняется. Конфликт типа/времени или неверный индекс
не исправляется таким способом. Визуальный вывод и уверенность остаются решением модели.

На одной RTX 4060 выполнять **одно видео одновременно**. Каждый вызов создаёт
spawn-процесс с моделями и завершает его, освобождая CUDA-контекст. Если Back 2
сам использует процесс, он должен разрешать дочерние процессы (`daemon=False`).
Точку запуска Windows-сервиса/скрипта защищать `if __name__ == "__main__"`.

После проверки исходных доказательств анализатор включает в 1–3 JPEG кадр,
который модель выбрала временем события. Возвращается точный timestamp этого
исходного кадра. Если для этого пришлось бы заменить один из трёх исходных
кадров-доказательств, находка отклоняется. Минимальное количество кадров и
временной интервал из политики не ослабляются. Это привязка доказательств,
а не независимая гарантия правильности выбранного моделью момента.

Между вызовами VLM освобождается неиспользуемый CUDA-кеш; веса остаются на GPU.
Приватный `AnalysisReport` дополнительно различает пик выделенной и зарезервированной
PyTorch-памяти. Поля публичных `Finding`/`EvidenceFrame` не изменены.
Аудит отдельных окон включается только `AnalyzerConfig(record_window_audit=True)`
для локальной диагностики; он содержит приватные описания и не предназначен для API.

Возможные исключения:

| Исключение | Значение |
|---|---|
| `VideoReadError` | Файл отсутствует, повреждён, слишком короткий или не декодируется |
| `ModelNotConfiguredError` | Веса не готовы, CUDA недоступна, нет разрешённых типов |
| `InferenceError` | Некорректный ответ модели, OOM или попытка сети |
| `AnalysisTimeoutError` | Процесс превысил дедлайн |
| `AnalyzerError` | Общий базовый тип ошибок рабочего процесса |
| `ValueError` | Некорректный каталог/параметры до запуска |

Все веса загружаются `local_files_only=True`, `trust_remote_code=False`.
В inference-процессе включён offline-режим и аудит, запрещающий DNS/сетевые
соединения. Видео, кадры и описания не отправляются наружу. Аудио и лица
не анализируются; роли не задаются координатами. Кеши и приватные диагностические
ответы пишутся только в `ANALYZER_TEMP_DIR` (по умолчанию `backend/analyzer/output/`).

## Проверка и оценка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
ruff check backend
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m backend.scripts.smoke_models
.\.venv\Scripts\python.exe -m backend.scripts.smoke_models --oom-check
.\.venv\Scripts\python.exe -m backend.scripts.evaluate
# Продолжение только с теми же данными, моделями, политикой и кодом:
.\.venv\Scripts\python.exe -m backend.scripts.evaluate --resume
# Приватные таблицы всех видео и списка на ручную проверку:
.\.venv\Scripts\python.exe -m backend.scripts.report_results
# После оценки — приватные JPEG с проверкой хеша исходных доказательств:
.\.venv\Scripts\python.exe -m backend.scripts.export_evidence
```

Pytest в основном использует явные синтетические mock-компоненты; это не метрики
нейросетей. Smoke/OOM и `evaluate` вызывают реальные локальные веса.
Ruff — отдельный инструмент разработки: при его отсутствии установите
`python -m pip install ruff`; для самого inference он не требуется.
Приватные таблицы, кадры, описания, веса и отчёты не входят в поставку Git.

Оценка разделяет исходный вердикт организаторов, визуальное описание,
предварительный тип, ручную проверку и нормативное основание. Классификация
рассчитывается только на проверенных метках; остальные положительные видео
сохраняются в бинарной оценке и локализации. Ошибка времени без порога считается
отдельно от ошибки по совпадениям до 3 с. Пропущенные из-за ошибки видео не
считаются отрицательными; их число отражается в покрытии.

Остающиеся ограничения: уверенность VLM не калибрована; новый ракурс отдельно
не проверен; выборка может пропускать краткие действия; маленькие предметы и
нечитаемые экраны ограничивают выводы. Обучения на видео жюри или других видео нет.
Результаты baseline 2f11600 от 17 октября 2026: 42/42 видео, 0 технических ошибок,
51 предсказанная находка, все ID из каталога, JPEG декодируются. Среднее/максимум
полного вызова 64.19/145.20 с; пик PyTorch allocator 5.803 GiB; после всех 42
процессов измерено 0 MiB по `nvidia-smi`. Контролируемый CUDA OOM обработан.
106 pytest-тестов, Ruff и `pip check` прошли. Подробнее — README и приватный
`backend/data/reports/evaluation.json`, checkpoint поддерживает `--resume`.

Программный контракт готов к интеграции с ручной проверкой результатов.
Автоматическое применение по качеству пока не готово: video precision 55%,
recall 50%, F1 52.38%, FP 9, FN 11. Таймкод MAE 6.813 с по 11 доступным
сопоставлениям; 3/22 событий до 3 с, 6/22 до 5 с. Подтверждённых типов только
3, правильных совпадений типа и времени среди них 0. Оставшиеся 19 положительных
меток требуют ручной проверки, все категории — правовой проверки. Нельзя
показывать уверенность VLM или совпадение ID как подтверждение виновности.

Одно дополнительное испытание исходных 848 px вместо 640 px превысило дедлайн
VLM и не вошло в основной прогон. Настройки 640 px сохранены; при изменении
разрешения или модели качество и бюджет нужно измерить заново.
