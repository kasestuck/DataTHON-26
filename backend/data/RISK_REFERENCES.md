# Описания возможных рисков и нормативные справки

`risk_references.json` — справочный каталог для отображения результата, а не перечень доказанных нарушений. Его ключи точно совпадают с 18 ID в `violation_types.json`. Каталог не используется при inference. Порог confidence, политика автоматической выдачи и контракт Finding сохраняются.

- `contextual_reference`: тематически относящийся документ; конкретный применимый пункт не проверен. Ссылка не доказывает нарушение.
- `internal_policy_required`: требуется применимый внутренний регламент банка и, для вопросов доступа и сохранности, проверка требований охраны. Регламент банка не предоставлен.
- `verified`: допускается только вместе с соответствующим проверенным документом, URL и конкретным пунктом в `rules.json`. Сам справочный каталог не подтверждает юридическое основание.

На 18.10.2026: 7 тематических справок, 11 вопросов внутреннего регламента, 0 подтверждённых оснований. Все записи `rules.json` сохранены в `needs_review`. Номера пунктов не назначались.

Основная справка: [постановление Правления Национального Банка РК от 29.11.2019 № 231](https://adilet.zan.kz/rus/docs/V1900019680) о кассовых операциях и инкассации банкнот, монет и ценностей. При проверке основной адрес «Әділет» возвращал страницу с требованием JavaScript; архивный официальный адрес не ответил вовремя. Реквизиты и тематика сопоставлены с индексируемой официальной карточкой документа. Полный действующий текст и связь конкретных пунктов с каждым событием не подтверждены. Поэтому ни одной категории не присвоен статус `verified` и в `rules.json` не добавлены источники. Сведения о возможных рисках сформулированы по существующим визуальным признакам, а не как цитаты закона.

Поле записи: `risk_description` (фиксированный возможный риск), `status`, `reference` (документ и официальный HTTPS URL либо null), `review_note` (что требует проверки). У тематической справки поле с номером пункта запрещено валидатором. Для `internal_policy_required` внешний источник не назначается.

API сохраняет обязательные поля результата и дополняет только `description`. Наблюдение модели сохраняется отдельно под подписью «Наблюдение». При отсутствии проверенного пункта показывается «Нормативное основание требует дополнительной проверки». Тематическая ссылка имеет явную оговорку; юридический вывод не делается. При отсутствии справочного файла API продолжает работать и выводит ту же оговорку.

Проверка:

```powershell
.\.venv\Scripts\python.exe -m backend.api.rules check
.\.venv\Scripts\python.exe -m backend.api.risk_catalog
```
